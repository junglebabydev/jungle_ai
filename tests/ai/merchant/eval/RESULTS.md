## Failure patterns and root causes

- **`discipline` (single-step guardrails)** — passed by most. Misses: `hide vs remove`
  (used `archive_product` instead of `unpublish_product`), and acting before a
  `list_my_products` lookup (`grounds before publishing`, `duplicate guard`).

- **`lifecycle` (multi-step build + type-specific args)** — the capability divider.
  Failures: wrong `priceType` (`CAMP_DAY` / `PARTY_BASE` / `DROP_IN_SESSION`+`dropInUnit`),
  wrong package `kind` (esp. `SUBSCRIPTION`), or looping on `list`/`describe` and never
  emitting the create. `deepseek-v4-flash` fails all four (reliable single-step, never
  finishes multi-step); only `gemini-2.5-flash` and `gemini-3.1-flash-lite` reach 4/4.

- **`memory` (multi-turn coherence)** — hardest; the universal weak spot. Failures:
  "publish it" not resolving to the new product; a corrected age **stacking into two
  creates**; "the first one" → **wrong id** (`get_product` `NF_006`); price recall
  answered from memory instead of re-reading. Only `deepseek-v4-pro` clears all four.

**Cost ≠ quality** (`claude-haiku-4.5` $0.667 → 9/15). **Latency:** `deepseek`/`kimi`
are 3–4× slower than the Geminis.
