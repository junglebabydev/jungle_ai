## What changed since the 3 July report

- **Multi-turn context carry (fixed).** The established activity/age/area is now
  accumulated deterministically from the conversation and re-stated to the model each
  turn, and the parsed age is pinned server-side. **`discovery-conversation` is now
  30/30 deterministic** (previously dropped the activity on refinements). The judged
  conversation rate stays low (strict multi-turn prose rubric — a known property).
- **Child-safety (hardened).** A distressed-child message is detected deterministically
  and answered with a caring, escalation-first reply *before* any model call — the
  safety-critical response no longer depends on model variance.
- **"Show data anyhow" (new).** When the exact request matches nothing, results are
  broadened progressively (activity term → filters → relax topic keeping age/area →
  whole-tab), so the parent never sees an empty grid. A broadened set carries
  `results.broadened = true` so the FE can label it "no exact matches — nearby options"
  and confinement invariants don't treat it as a leak.
- **Latency.** Leading with `gemini-3.1-flash-lite` (~3.2s/scenario under contention)
  instead of `deepseek-v4-flash` (17.8s in the A/B) is the dominant win. An optional
  `CONCIERGE_SEARCH_FIRST` flag (off by default) collapses the turn to a single model
  call for a further ~2.5–3× speedup; kept off pending quality validation.

current run above for the lead-config numbers, but the comparison, cost, and insights

dimensions against the real `/concierge/chat` endpoint, scored on the HTTP search
results (deterministic) plus a neutral LLM grader (`openai/gpt-4o-mini`) on the prose.

## Failure patterns and root causes (3 July)

- **`shared-robustness` (8/9 for all six)** — one scenario, `oversized spam input`, fails
  for every model: the harness posts a >500-char body and the DTO validator (correctly)
  rejects it with a 400. A **suite/harness artefact**, not a model differentiator.
- **`discovery-conversation` and `discovery-explorer-map` judged rates are low across the
  board** despite high deterministic scores — the strictest multi-turn / coverage prose
  checks; the grader penalises any dropped context or missing trail acknowledgement. A
  known property of these judged rubrics, affecting every model.
- **`gpt-5-nano`** — the only model weak on correctness (82%): frequently fails to run the
  right search, and a reasoning model at 32.6s/scenario — disqualifying regardless.
- **`gemini-2.5-flash-lite`** — 97% correct but only 64% judged: weaker, sometimes
  terse/empty prose. Cheap and fast but not lead-quality.
- **`deepseek-v4-flash`** — genuinely good prose (80% judged) but 17.8s/scenario; the
  latency, not the quality, is why it is a fallback rather than a lead.

**Cost ≠ quality, and speed is the real tie-breaker.**
